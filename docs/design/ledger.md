# ledger

## Overview

A second identity, cooler and flatter, kept in the tree so the swap is proven rather than claimed: a golden fails when two identities render the same pixels.

This identity is not the one the app ships — `DESIGN.md` at the repository root is. It is kept because a design system that has only ever rendered one look has not been shown to be swappable:

```dart
Design(
  spec: DesignSpec.ledger(),
  child: child,
)
```

**This file is generated.** Every value above and below is read out of `lib/theme/spec/` by `test/theme/design_md_test.dart`. Editing it by hand fails `make design-md`; changing a token and forgetting to re-render fails the same way. Change the spec, then run `make design-md-update`.

Two conventions this file adds to the format:

- **`dark-` prefixed colour tokens.** The frontmatter carries one flat colour map and this app has two palettes, so every light role appears again with a `dark-` prefix. A consumer that only wants one palette can ignore the prefixed half.
- **A `## Motion` section.** Duration, curve and spring are real tokens here and the eight canonical sections have nowhere to put them.

Roles, not hues. Nothing in `lib/` names a colour; it names the job the colour does, which is why the whole app changes identity on one line.

Both palettes are grown in OKLCH from seeds rather than typed, so the steps stay in relation to each other. Contrast is gated, not trusted: `make palette-lint` (K1..K11) fails the build on a pair that misses its WCAG floor, in either brightness.

## Typography

`Satoshi` for text, `Satoshi` for display and headline, falling back to Roboto.

Sizes are not typed. They are powers of 1.2 around two anchors — 13.2px for running text, labels and controls, 16.5px for display and headline. Two anchors because "make the text smaller" means one thing for a dense list and the opposite for the one title on the page. Moving an anchor re-proportions its half of the scale and leaves every relationship inside it where it was.

## Layout

One grid: 4px, with eight steps grown off it and a density multiplier (0.92) that makes the whole layout airier or denser without a widget being edited.

| Step | Value |
| --- | --- |
| `hairline` | 1.84px |
| `xs` | 3.68px |
| `sm` | 7.36px |
| `md` | 11.04px |
| `lg` | 14.72px |
| `xl` | 22.08px |
| `xxl` | 29.44px |
| `xxxl` | 44.16px |
| `page-gutter` | 18.4px |

`page-gutter` is its own value rather than a step, because the gutter answers to the device and the steps answer to each other. It has exactly one owner — `DSPage`, `DSFormPage` and `DSGutter`. A screen that applies it itself fails `ui_lint`.

The rules a phone layout is held to:

- **Primary actions go bottom, full width, above the safe area** — not bottom-right, which is the desktop pattern.
- Titles, status and identity go top; a thumb lives at the bottom.
- Destructive actions never sit adjacent to a common one.
- Positions come from the reading direction (`start` / `end`), never from the screen.
- Every async surface renders four states — loading, empty, error, success. A missing one is a bug, not a gap.

The long form is [docs/UX.md](../UX.md) and [docs/principles/](../principles/).

## Elevation & Depth

Five levels, and every one of them is two shadows: a contact shadow that says the surface is touching something, and an ambient shadow that says how far off the page it is. One shadow reads as a sticker.

| Level | Value |
| --- | --- |
| `none` | 0 |
| `low` | 1 |
| `medium` | 2 |
| `high` | 4 |
| `highest` | 8 |

Contact: 1px blur at 1px, alpha 0.075 light / 0.25 dark. Ambient: 5px blur at 1.7px, alpha 0.055 light / 0.15 dark. Dark needs roughly four times the alpha for the same read, which is why the two are separate numbers rather than one opacity.

Shadows are tinted, never black. Details in [docs/principles/depth-and-materials.md](../principles/depth-and-materials.md).

## Motion

| Token | Value |
| --- | --- |
| `instant` | 100ms |
| `fast` | 200ms |
| `normal` | 300ms |
| `slow` | 500ms |
| `press` | 120ms |
| `press-release` | 180ms |
| `route-enter` | 280ms |
| `route-exit` | 220ms |
| `shimmer` | 1200ms |
| `reveal-step` | 45ms |
| `speed` | 0.85x |
| `springiness` | 1.25 |

Four curves — `enter`, `exit`, `emphasize`, `standard` — and three springs: `snappy`, `gentle`, `bouncy`. A spring is used where a gesture hands off to an animation and the user should not feel the seam; a curve is used everywhere else.

Spend motion where it is remembered — the **peak** of the interaction and the **end** of it — and keep the rest of the screen quiet. Motion on a row that does nothing reads as lag. [docs/principles/emotional-design.md](../principles/emotional-design.md) is the owner of that reasoning; [docs/principles/motion.md](../principles/motion.md) is the owner of these numbers.

The frontmatter `rounded` map carries the Material column, because the format has one value per role. `pill` is a stadium rather than a large radius, and is never scaled — scaling it turns a capsule into an arbitrary rounded rectangle. ## Do's and Don'ts

Most design-system documents are advisory. This half is not: every rule below is a build failure with a name, and `dart run tool/ui_lint.dart` is what fails. The rule id is the one it prints.

| Rule | Don't | Do |
| --- | --- | --- |
| `hardcoded-hex` | Write a `Color(0xFF…)` outside `lib/theme/` | Read the role: `context.design.palette.primary`. |
| `hardcoded-color` | Reach for a Material colour constant | Every colour in this document has a role name. Use it. |
| `hardcoded-radius` | Type a corner radius | `context.shapeOf(AppShape.card)` for the border, `context.radiusOf(...)` for the number. |
| `hardcoded-icon-size` | Size an icon by hand | The `icon` component group below owns five sizes. |
| `hardcoded-duration` | Type an animation duration | `context.design.motion.fast` and its neighbours. |
| `hardcoded-curve` | Type a curve | `motion.enter`, `motion.exit`, `motion.emphasize`, `motion.standard`. |
| `hardcoded-text-style` | Build a `TextStyle` at a call site | Name a type role. There are fifteen plus `micro`. |
| `physical-direction` | Position with `left` / `right` | `start` / `end`. An inset written the physical way lands on the wrong edge in Arabic. |
| `raw-button` | Use a Material or Cupertino button | The kit owns it. `docs/references/design-system-reference-llms.txt` names the replacement for each. |
| `raw-card` | Use `Card` | `DSCard`, which reads elevation and shape from this spec. |
| `raw-list-tile` | Use `ListTile` | `DSListTile` — the row heights below are its, not Material's. |
| `raw-dialog` | Call `showDialog` directly | `DSDialog`. And ask first whether the answer really blocks the next step — if it does not, it is a sheet. |
| `raw-bottom-sheet` | Call `showModalBottomSheet` directly | `DSBottomSheet`, which already handles the safe area and the grabber. |
| `token-namespace` | Invent a spacing or colour namespace | There is one spec. `context.design.*` is the whole surface. |

A genuine exception is waived inline with `// ui-lint: allow <rule-id> — <reason>`, which is a line somebody has to write and a reviewer can find. Silence is not an exception.

Three more that no linter can catch, and that are the difference between a screen that passes and a screen that is good:

- **Do not widen a token to make one screen work.** A token change is every screen's change.
- **Do design the passive states.** An empty state gets guidance, a reason and one action — not a grey sentence.
- **Do not spread polish evenly.** Pick the peak and the end. Everything else stays quiet.
